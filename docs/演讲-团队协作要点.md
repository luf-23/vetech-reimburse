## 2. 提交规范（本项目实际用法）

### 2.1 推荐格式（后期已统一）

| type | 含义 | 本仓库示例 |
|------|------|------------|
| `feat` | 新功能 | `feat(backend): 实现报销单与主数据 REST API 及 MySQL 持久化` |
| `fix` | 修复 | `fix(frontend): 固定报销列表底部分页…` |
| `refactor` | 重构 | `refactor(backend): 使用 MyBatis-Plus，改用 application.yml…` |
| `docs` | 文档 | `docs: 补全 README 启动步骤与数据库说明` |

**scope 可选：** `(frontend)` / `(backend)`；前后端都改时可省略 scope，如 `fix: 分摊比例与金额校验与前端一致…`。

**演讲强调：** 从「能跑」到「规则对齐、文档齐全」是迭代出来的；Git log 本身就是项目演进记录。

## 4. 联调约定

| 项 | 约定 |
|----|------|
| **端口** | 后端 8080，前端 Vite 开发服（通常 5173） |
| **代理** | 前端 `vite.config.ts` 将 `/api` 代理到后端，**不在后端开 CORS** |
| **主数据 ID** | 前端 `masterData.ts` 与 `02_data.sql` 示例 ID 必须一致；后端只存字符串 ID |
| **启动顺序** | 先 MySQL 建表 → 后端 → 前端（见根目录 README） |
| **接口变更** | 改路径/DTO 时同步改前端 `api/reimburse.ts` 与文档（`docs/API接口定义文档.docx`） |

## 5. Postman 接口测试

**环境变量：** `baseUrl = http://localhost:8080`

| 场景 | 请求 | 检查点 |
|------|------|--------|
| 健康/列表 | `GET {{baseUrl}}/api/reimburse/list?page=1&size=10` | `code === 0`，`data.records` 有数据 |
| 详情 | `GET {{baseUrl}}/api/reimburse/detail/1` | 含 itineraries、subsidies、allocations |
| 校验失败 | `POST {{baseUrl}}/api/reimburse/validate` | Body 中分摊比例合计 ≠ 1 → `valid: false` + 中文 message |
| 不存在 | `GET {{baseUrl}}/api/reimburse/detail/99999` | HTTP 404，`code === -1` |
| 新建/更新 | `POST /create`、`PUT /update/{id}` | 返回完整 `ReimburseFormVO` |

**演讲强调：** 后端可**脱离前端**用 Postman 自测；前端同学在后端未就绪时也可先用 API接口文档确认接口契约。  
**异常用例必测：** 分摊 ≠ 100%、金额 ≠ 补助合计、补助未关联行程、复制后 id 重复。
