# 差旅报销系统 — 前端演讲要点

> 技术栈：Vite 7、Vue 3.5、Vue Router 5、Element Plus、TypeScript  
> 路由：`/` 列表 · `/reimburse/form` 新建 · `/reimburse/form/:id` 编辑

---

## 1. 列表页（`ReimburseList.vue`）

| 要点 | 说明 |
|------|------|
| **底部分页器固定** | `height: 100vh` + `flex` 纵向布局；表格区 `flex: 1` 可滚动；分页器 `flex-shrink: 0` 固定在卡片底部（顶部分割线 + 阴影），滚动表格时分页始终可见 |
| **分页查询** | `GET /api/reimburse/list`，传 `page`、`size`（默认 10，可选 10/20/50）；翻页、改每页条数时重新请求 |
| **多条件筛选** | 单号、标题、事由（模糊）；公司、部门、报销人、业务类型（精确）；参数与后端 `ReimburseListQueryDTO` 一一对应 |
| **业务类型末级校验** | 只能选末级节点，选父级时提示「请选择末级业务类型」并回退 |
| **CRUD** | 新建、编辑、复制、删除；删除/复制带二次确认；复制成功后回到第 1 页 |

**演讲强调：** 固定布局 + 服务端分页，避免一次拉全量；筛选字段与后端 DTO 对齐，联调时参数名可直接对照。

## 2. 表单页布局（`ReimburseForm.vue` + `reimburse.css`）

| 要点 | 说明 |
|------|------|
| **固定表头** | 单据标题、提单日期 `position: fixed` 在视口顶部 |
| **固定底栏** | 保存 / 提交 / 关闭按钮不随内容滚动 |
| **中间滚动** | 基础信息、行程、补助、合计、分摊、备注六大区块在中间区域纵向滚动 |
| **分区折叠** | 各 `SectionPanel` 可折叠 |
| **提单日期** | 新建取当天；编辑取已保存数据 |

## 3. 行程与补助一一对应

| 要点 | 说明 |
|------|------|
| **自动同步** | `syncSubsidiesWithItineraries()`：行程增删改时同步补助；无行程则清空补助 |
| **关联字段** | 补助 `itineraryId` ↔ 行程 `id`；新增行程时 `buildSubsidyFromItinerary()` 生成默认补助（路线、天数、日历） |
| **实时联动** | `watch` 行程 id 列表变化 → 重算补助行 |
| **校验** | `validateItinerarySubsidyLink()`：数量相等、双向关联、不可重复、不可遗漏 |
| **行程校验** | 同一人日期区间不可重叠（`datesOverlap` / `isItineraryDuplicate`）；出行人、城市、日期、说明必填 |

**演讲强调：** 前端实时联动 + 提交时校验；规则与后端 `ReimburseFormValidator.validateItinerarySubsidyLink` 一致。

## 4. 补助日历（`SubsidyCalendarDialog.vue`）

| 要点 | 说明 |
|------|------|
| **按日勾选** | 餐补 / 交通 / 通讯；支持按日、按列、全选（含半选态） |
| **标准额** | 餐补按城市类型 100/80/50；交通、通讯各 40 |
| **金额上限** | 勾选项须在 0 ~ 标准额之间（`validateSubsidyAmounts`） |
| **合计** | 仅统计已勾选项（`calcCalendarTotals`）；确认后回写 `subsidyAmount` 与各分类合计 |
| **展示兼容** | `normalizeSubsidyCalendar()`：未勾选项展示标准额，兼容后端 amount=0 的历史数据 |

---

## 5. 分摊金额与比例「零误差」

| 要点 | 说明 |
|------|------|
| **比例合计 100%** | `ratio` 为 0~1 小数，合计须为 1（容差 0.001） |
| **金额 = 补助总金额** | 补助或比例变化时 `distributeAllocationAmounts()` 重算 |
| **差额补首行** | 除首行外先四舍五入到分；同比例时其余行相等；**差额补第一行**，保证 `sum(amount) === subsidyTotal` |
| **与后端对齐** | 算法与 `AllocationAmountUtil.java` 一致（提交 `bf4a128` 前后端统一） |

**演讲强调：** 典型财务尾差问题——不能各行独立四舍五入，否则会出现 0.01 元误差。

---

## 6. 提交校验（双重校验）

| 步骤 | 说明 |
|------|------|
| 前端 | `validateReimburseForm()`：基础信息、行程、补助关联、日历金额、分摊 |
| 后端 | `POST /api/reimburse/validate`；后端不可用时前端校验通过可降级继续 |
| 保存 | 新建 `POST /create`，编辑 `PUT /update/{id}` |

## 7. 工程化与目录

| 文件 | 职责 |
|------|------|
| `api/http.ts` | 统一 `fetch`，解析 `{ code, message, data }`，`code !== 0` 抛 `ApiError` |
| `api/reimburse.ts` | 列表、详情、CRUD、复制、校验 |
| `utils/reimburse.ts` | 日期、日历、分摊算法、行程补助同步 |
| `utils/validateReimburse.ts` | 表单校验（与后端规则对齐） |
| `utils/normalizeReimburse.ts` | 后端详情 → 前端表单（类型转换、日历规范化） |
| `utils/businessTypeTree.ts` | 业务类型树与末级判断 |
| `data/masterData.ts` | 主数据写死，ID 与 SQL 示例一致 |
| `composables/useMasterData.ts` | 主数据注入 |
| `vite.config.ts` | `/api` 代理到 `http://localhost:8080`（消除跨域） |
