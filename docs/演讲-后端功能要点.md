# 差旅报销系统 — 后端演讲要点

> 技术栈：Spring Boot 3.2、MyBatis-Plus 3.5、MySQL 8、JDK 17  
> 接口前缀：`/api/reimburse` · 默认端口：`8080`

---

## 1. 表结构设计（`resources/SQL/01_schema.sql`）

| 表 | 说明 | 设计要点 |
|----|------|----------|
| `reimburse_doc` | 报销单主表 | 单号唯一索引；冗余 `subsidy_amount` 便于列表展示；主数据只存 ID |
| `reimburse_itinerary` | 补录行程 | `doc_id` 外键，`ON DELETE CASCADE` |
| `reimburse_subsidy` | 补助明细 | `itinerary_id` 关联行程；`calendar_json` 存日历 JSON |
| `reimburse_allocation` | 费用分摊 | `ratio` + `amount` + `sort_order` |

**演讲强调：**

- **一主三子**，删主单级联删子表  
- **主数据不入库**（公司、部门、人员等由前端 `masterData.ts` 维护）  
- **外键 + 索引**：单号唯一；报销人、部门、公司、业务类型、创建时间可查  

示例数据：`02_data.sql`（含行程、补助、分摊样例）。

## 2. 分层架构

```
controller/   → REST，参数接收 + Result 包装
service/      → 业务逻辑、事务、主子表保存
mapper/       → MyBatis-Plus + XML 自定义查询
entity/       → 与表一一对应
dto/          → 入参
vo/           → 出参
util/         → 校验、分摊算法
common/       → Result、PageResult
handler/      → 全局异常
config/       → 分页插件
```

## 3. DTO / VO 设计

| 类型 | 类 | 用途 |
|------|-----|------|
| DTO | `ReimburseFormDTO` | 创建/更新，含嵌套行程、补助、分摊 |
| DTO | `ReimburseListQueryDTO` | 列表筛选 + page/size |

| VO | `ReimburseListItemVO` | 列表行（不含子表） |

**演讲强调：** DTO 入参、VO 出参、Entity 持久化，职责分离；`aae055b` 曾将 API 路径语义化并合并表单 DTO/VO。

## 4. Result 统一封装（`common/Result.java`）

```java
Result.success(data)   // code = 0
Result.error(message)  // code = -1
```

- 所有 Controller 返回 `Result<T>`  
- 分页：`Result<PageResult<ReimburseListItemVO>>`  
- `PageResult`：`records`、`total`、`page`、`size`  

前端 `http.ts` 只解析 `data`，异常看 `code` 与 `message`。

## 5. 全局异常处理（`GlobalExceptionHandler`）

| 异常 | HTTP | 响应 |
|------|------|------|
| `NoSuchElementException` | 404 | `Result.error("报销单不存在")` 等 |
| `IllegalArgumentException` | 400 | 校验失败、参数非法 |

Service 抛异常，Controller 不写 try-catch，`@RestControllerAdvice` 统一转 Result。

## 6. @Transactional 事务

| 方法 | 注解 |
|------|------|
| `list` / `getById` / `validate` | `@Transactional(readOnly = true)` |
| `save` / `delete` / `copy` | `@Transactional` |

**`save` 流程（同一事务）：**

1. 更新时 `deleteChildren` 删旧子表  
2. `AllocationAmountUtil.distribute` 重算分摊金额  
3. `ReimburseFormValidator.validate` 校验  
4. 写主表 → 写子表（行程 id 映射后写补助）→ 回写主表 `subsidy_amount`  

任一步失败整笔回滚。

**复制（`copy`）：** 读源单 → 清 id、改标题后缀 → 行程用临时 id 重建补助关联 → 走 `save`（`16f31ad` 修复复制后 id 与源单相同的问题）。

## 7. util 校验与工具类

### `ReimburseFormValidator`

- 主表必填与长度（标题 500、事由 500、备注 1000）  
- 至少一条行程；补助与行程一一对应  
- 分摊比例合计 = 100%（容差 0.001）  
- 分摊金额合计 = 补助总金额（`normalizeMoney` 比较）  

### `AllocationAmountUtil`

- `distribute(total, allocations)`：差额补首行  
- `normalizeMoney(value)`：保留 2 位小数  

**演讲强调：** 校验集中在 util，前后端规则对齐（`bf4a128`）；除不尽时差额加在首行公司。

## 8. 分页查询

- `MybatisPlusConfig`：`PaginationInnerInterceptor`（MySQL，单页最大 500）  
- `ReimburseDocMapper.xml` → `selectPageByQuery`：动态 WHERE + `ORDER BY create_time DESC, id DESC`  
- 复杂条件放 XML，Mapper 接口只声明方法（`cc12f57`）
